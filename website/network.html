What you are looking at

Four things on one page

Globe and flat map

The same federation, two projections. The globe is for the shape of the thing — three continents, one hub — and the flat map is for reading labels and clicking sites. Arcs run from the coordinator to each participating site.

Experiments

Every site is a card: institution, city and country, the experiments it takes part in, and the samples it declared for each. Filtering by experiment redraws the map to that experiment's federation.

Results

Selected figures, tables and reports from completed runs, opened in place beside the map rather than as a directory of files somebody has to be sent.

Runs

A live run streams onto the same map as it happens — per round, per site — and a finished run can be replayed from its recorded events.

Why it works this way

Three decisions worth knowing about

The map exists before any run does

It is drawn from federation.yaml alone, so the day the config names a partner, that partner is on the map. That is what makes it a picture of the network rather than a dashboard for one job — partners are recruited and stand up endpoints long before anybody launches anything, and there has to be something to look at in the meantime.

Geography is declared, not detected

Site coordinates come from federation.yaml and are never resolved from an IP address. A partner's compute node has no outbound web access, so the lookup would fail; if it succeeded it would return the institution's border router rather than the cluster; and it would add an outbound call from inside a partner's security boundary for the sole purpose of drawing a dot. A site with no coordinates is reported as unplaced rather than drawn at a guess.

What is deliberately not published

Site names, countries, coordinates, sample counts and experiment names are in the published data by design — that is the map. Service accounts, cluster paths, the coordinator's Globus identity and, by default, full endpoint UUIDs are not. Endpoint UUIDs are truncated to a fingerprint unless you opt in.

Your own federation

Three static files anyone can host

The export is a viewer, a metadata file and an index. No server of ours, no Python at the other end — drop it on GitHub Pages, an institutional web host, or any object store, and everyone in your federation has the same page. 

pip install 'appfl-bio-suite[watch]' -c constraints.txt

appfl-bio-suite watch build               # draw it from federation.yaml
appfl-bio-suite watch serve               # look at it locally
appfl-bio-suite watch export --out site/  # three static files anyone can host
appfl-bio-suite run gwas --watch          # a live run, on the same map
Check what you are publishing. watch export writes the site names, countries, coordinates, sample counts and experiment names that make the map a map. Pass --experiment to publish one experiment's federation, and read docs/coordinator/network-map.md before handing the URL out.

Appending ?view=globe to the viewer URL opens it on the globe, which is what this page's embed does.

Built on

HiveWatch and APPFL

HiveWatch

APPFL's monitoring toolkit. It supplies the event schema, the map metadata format, the SSE server and the Leaflet viewer. What this suite adds is the federation itself: HiveWatch knows how to draw a client, and federation.yaml knows who the clients are.

APPFL

The federated learning framework underneath every experiment in the suite — the aggregators, the client trainers, and the communication layer this project drives over Globus Compute.
