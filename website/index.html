About

One coordinator, many institutions, nothing pooled

The coordinator runs a driver and an aggregator. Every partner runs a privileged process on their own cluster, against data that never leaves it. What crosses the wire is what the experiment's maths needs — model weights, or per-variant summary statistics — and nothing else.

What you need

Python 3.12. A Globus account. Partners willing to run a privileged process on their own clusters.

What you do not need

A shared filesystem, a VPN, matching operating systems or schedulers, or inbound network access to anybody.

Experiments

Three experiments, three different federations

They are deliberately unalike. One is multi-round training on a public benchmark; two are single-round statistical federations where the aggregation is the science.

Multi-round · FedAvg

FLamby Fed-Heart-Disease

Multi-round federated training on a public tabular benchmark with natural hospital splits. The scientific point is not the model — it is the infrastructure claim: that APPFL over Globus Compute can drive a genuine multi-round job across separately administered clusters on different continents and reach the published baseline.

Single round · Meta-analysis

Federated GWAS

A genome-wide association study with polygenic-score evaluation, across institutions on different continents. Each site runs a complete local GWAS and sends only per-variant effect size, standard error and minor-allele frequency; the server combines them by inverse-variance fixed-effect meta-analysis.

Single round · Exact

Cross-ancestry fine-mapping

A GWAS says this locus matters; fine-mapping asks which variant in it is causal. That needs the linkage-disequilibrium structure, which is exactly what does not decompose into per-variant summaries. Credible sets are built from per-site second moments — and the federated fit equals the pooled fit, rather than approximating it.

Design

How it is put together

Most of the difficulty in a cross-institution run is not the maths. It is version skew, half-written configs, and instructions that a partner has to interpret. Each of these is a decision about that.

One config file

federation.yaml declares who you are, who your partners are, and what each is doing. Every generator, config, document template and check reads from it. Nothing in src/ contains a coordinator identity, an endpoint UUID or a site name — and CI verifies that, because the repo has to work for someone who is not its author.

Generated partner bundles, not templates

A bundle is a directory with a partner's configuration fully resolved: their site ID, their data assignment, your identity, their scheduler's provider block — plus their two setup documents with no placeholders left to interpret.

A closed set for partner-facing content

Bundles are built from docs/partner/ and nowhere else, enforced in code, so nothing outside that tree can reach a partner by accident.

Exact version pinning

Every site runs byte-identical versions of the Globus Compute stack. Skew does not fail at install time; it fails as a deserialization error several rounds into a run on somebody else's cluster. constraints.txt pins it and preflight --check pins verifies it.

Failures that name the fix

The troubleshooting registry is indexed by symptom, and gives the mechanism alongside the fix — so a partner's error message resolves to a cause rather than to a support thread.

The CLI

appfl-bio-suite preflight [--experiment X]           environment, pins, configs, endpoints
appfl-bio-suite endpoint status [SITE]               is it online
appfl-bio-suite endpoint smoke [SITE]                round-trip: does it actually work
appfl-bio-suite identity validate <mapping.json>     catch mapping bugs offline, in a second
appfl-bio-suite simulate EXPERIMENT --scenario NAME  generate and split synthetic data
appfl-bio-suite run EXPERIMENT                       run it
appfl-bio-suite partner-bundle EXPERIMENT --site X   a partner's complete setup package
appfl-bio-suite watch build | serve | export         the federation, on a map
appfl-bio-suite ga4gh duo | drs | trs | tes          data use, data objects, tools, tasks

Standards

GA4GH, for the parts that used to be assumptions

The fine-mapping experiment is assembled out of four GA4GH specifications, each closing a hole the design otherwise had.

ServiceNameAnswers
DUOData Use OntologyMay this site's data be used for this study?
DRSData Repository ServiceExactly which bytes did a site compute over?
TRSTool Registry ServiceExactly which tool version computed them?
TESTask Execution ServiceRun that tool, there, on those bytes.
Together: a named tool version, pinned by checksum, runs over content-addressed data whose use terms permit the study that dispatched it. Every clause of that sentence used to be an assumption.

A site enforces its own consent code

Each bundle carries a DATA_USE.json, and the site's worker matches it against the study the coordinator declared — refusing before it opens a genotype file, on its own hardware, in the account it controls. The coordinator runs the same check offline before dispatch, but that one only saves a queue wait.

Bundles are content-addressed

A sha-256 per file and a Merkle id over the set, so "did this site run on the bundle I cut for it" is a string comparison. Without it, a site running last month's bundle produces well-formed aggregates over the wrong individuals, pools without complaint, and is wrong in no visible way.

Results name the code that made them

The tool pin covers the source of the two modules APPFL ships to workers, is verified at launch, and is written into every run's ga4gh_provenance.json alongside what each site attests to having actually done.

All of it is opt-in per experiment: a federation.yaml with no ga4gh blocks produces byte-identical configs to the ones it produced before any of this existed. Read the GA4GH design →

Reproducibility

A run you can check afterwards

Every simulation writes a manifest

The scenario, every seed, the suite commit, input and output checksums, and package versions. simulate gwas --verify <manifest> confirms a rerun mechanically.

The GWAS simulation is deterministic

For a fixed seed, all 35 outputs are byte-identical, verified against recorded checksums.

Known limits are written down

The data documents state which input cohort is not regenerable, and what the shipped substitute does and does not reproduce.

The network map

Everyone in the federation opens the same page

Every institution on a world map — flat or on a globe — which experiments each runs, what kind of data each holds, how many samples they declared, and whether their endpoint is answering. It is drawn from federation.yaml alone, so the map exists before any run does. The live preview draws twenty invented institutions on six continents.

Quickstart

Prove the install works before you recruit anybody

A complete federation on one machine — no partners, no network, and nothing to fill in first. This is the same pair of commands CI runs. 

# install
git clone https://github.com/mfjoel01/appfl-bio-suite.git
cd appfl-bio-suite
python -m venv .venv && source .venv/bin/activate
pip install -e ".[all]" -c constraints.txt

# a whole federation, on one machine
appfl-bio-suite simulate gwas --scenario ci-tiny --out /tmp/gwas-ci
appfl-bio-suite run gwas --config loopback --driver serial --data-root /tmp/gwas-ci

# then stand up a real one
cp federation.yaml.example local/federation.yaml
$EDITOR local/federation.yaml
appfl-bio-suite preflight

docs/coordinator/new-federation.md takes you from here to a running experiment across institutions you recruit yourself.
